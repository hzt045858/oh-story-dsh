## 明确的适配

2026-09-17 增加 [全流程可控契约](workflow-control.md)：不是新增固定画风，而是把既有全量建库、
主题/全局/图文模型、原创写作、生成、审核、排版和发布要求接到可执行的模型验收与单篇任务版本。
模型内部 schema_version 保持 1；新图文计划与图文审核为 2；已有资料、人工规则和旧创作记录保留，显式迁移后才适用新门禁。

当前产品流程以“先分析全部文章并保存风格，后续按风格生成”为准。V5.0 中每次写作调用完整范文的
步骤已取消；原文检索仅用于建库深析、风格更新、证据追溯或用户明确指定的附加资料。

1. 原文以启动目录作为单作者根；这里按公众号账号隔离，参考目录可单独绑定，适应多个账号。
2. 用户提供的 V5.0 要求原件只读，也接受 HTML；这里保留全部原件，识别重复，优先选正文干净的 Markdown。不得把删除 HTML 归为该提示词要求。
3. 不确定的研究不改写为无来源的“有研究显示”。核实出处，否则删除事实断言或明确表达为个人判断。
4. 流程分享中的高阅读选题经验与 V5.0 提示词分开记录。这里分析用户提供的高阅读选题的需求和切入点，保留可核实的阅读量，
   不编造爆款数据，不要求复制原标题。新增选题保持原创观点、案例与表达。
5. 原文的排版学习被保留，增加图片文字、画面、图文关系、多图推进和时期差异分析。OCR 仅辅助识别图片文字，不能代替看图。图片型账号保存独立图文模型，并默认生成实际图片正文；缺图记为待生成。详见 [visual-style.md](visual-style.md)。这会改变图片型账号的创作与完成条件，不只是增加装饰配图。
6. 原文“上传，群发”落地为官方 API 草稿上传、回读、公开发布、群发和状态查询；
   配合多账号注册表、批次计划、定时执行入口与持久回执，实际外部动作沿用用户的明确范围。
