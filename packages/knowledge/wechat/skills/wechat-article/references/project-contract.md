# 账号与文件契约

执行约束以 [workflow-control.md](workflow-control.md) 为准。本文描述目录和资料结构；新任务使用 controlled-wechat-v1，
旧 style-model-v1 文件保留，迁移需重审当前真实输入并显式 --migrate，不生成虚假的历史通过记录。

## 目录

账号默认根为 `公众号/<账号>/`，同一账号只绑定一个参考文章根，多个作者不得悄悄混库。
已有资料可以在用户指定的其他位置；原件只读，不移动、不重命名、不插入分类信息。

按实际阶段生成文件，不把空文件当完成。文件名使用稳定 ID 与安全短标题，不把原始选题直接当路径。
`账号.json` 记录稳定 id（与发布注册表一致）、账号名称、新署名（可空）、受众、参考根、语言、视觉风格、图片数量上限、
默认主题与已有排版参考；不放 API Key、cookie 或 app secret。
另记录 `content_mode`（`text`/`mixed`/`image-led`）和图文模型路径；形式按实际全库分析确定，用户明确要求优先。
图文模型、计划及检查的结构与完成条件见 [visual-style.md](visual-style.md)。
多账号公共注册表放在各账号根的上一级 `accounts.json`，发布计划也放在那里。
注册表仅保存 AppID 与密钥环境变量名，具体格式和发布状态见 [publishing.md](publishing.md)。

## 清单与标注

扫描支持 UTF-8/UTF-8 BOM/GB18030 的 Markdown、TXT、HTML 和 DOCX 正文提取。
HTML 优先提取 `#js_content` 或 `<article>`；通用页面需 Agent 检查菜单、广告等污染。
PDF/RTF 等被记录为待转换，使用当前环境可见的解析工具输出到单独的暂存目录后人工核对，
再明确作为一个新参考根建库或整理入参考根；不把附件静默当作已读正文。

清单保留稳定 ID、源文件哈希、正文哈希、读取状态与来源路径。删除或修改原件会使标注过期；
扫描不覆盖 `文章标注.json`、文章卡片、风格模型或人工规则。

Agent 逐篇读完正文后维护 `文章标注.json`（JSON 数组），每项至少是：

```json
{
  "id": "ART-001",
  "source_sha256": "从资料清单复制的源文件哈希",
  "primary_category": "职场",
  "subtopic": "领导关系",
  "expression_task": "识别判断",
  "audience": "职场普通员工",
  "title_formula": "现象与判断",
  "structure": "具体场景-机制-边界-行动",
  "tone": "克制直白",
  "core_question": "如何区分暂时没任务与持续被边缘化",
  "core_claim": "需要观察任务、信息与反馈的持续变化",
  "keywords": ["领导关系", "边缘化", "工作分配"],
  "variant_group": "工作分配信号",
  "duplicate_status": "独立文章",
  "time_period": "2026-08",
  "publish_date": "2026-08-01",
  "author": "资料中的署名",
  "source_type": "公众号导出",
  "platform_template_flag": true,
  "author_identity_flag": true,
  "identity_terms": ["实际出现的原账号名"],
  "quality_notes": "末尾推广已识别，不用于学习",
  "confidence": "高"
}
```

日期不知道就留空，不用文件修改时间冒充发布时间。每篇仅一个主类、子题和主要表达任务。
index 合并的是与当前源文件哈希匹配的标注；缺失/过期记录保持 pending，不能参与正常检索。
图片正文还需匹配 ingest 保存的 analysis_input_sha256，并在实际核对后填写 content_reviewed/visual_reviewed。
index/retrieve 会校验原件、提取视图和本地图片哈希；单纯 OCR 提取成功不能让图片文章成为 ready。
OCR 低置信行、空识别结果与动画图片分别保留待核对信息，不自动替 Agent 认证读取质量。
`duplicate_status` 标为 `完全重复` 的记录不参与范文检索，手动指定 ID 也会拒绝；近似重复或同题变体仍由 Agent 按内容复核。
`identity_terms` 只记录真实出现的身份/品牌/广告词，不把“职场”等普通主题词列为禁用词。

## 状态与更新

状态记录当前阶段、已扫描/可读/已标注/卡片/重复/变体/模型数量、模板与身份污染数量、
创作系统是否完成、平台模板与身份过滤规则路径、
置信度、未读与待复核项、代表样本、默认字数、下次需要读取的文件。
更新资料时先 ingest（包含 scan），再重读新增/变更文章和图片，增补标注后 index，复核受到影响的主题与全局模型。
删除的文章在清单保留 missing 记录以防 ID 被复用；它们不参与检索。

每个风格模型的证据保存文章 ID + source_sha256，便于资料变化后判断哪些结论需要重新验证。
上述原文哈希检查在资料更新阶段执行；日常创作加载已保存模型，不扫描原文或要求参考根可访问。
`创作记录.json` 新任务使用 `workflow: "controlled-wechat-v1"`，由 article_workflow.py lock 写入，保存本次模型路径、文件 SHA256、任务签名、单图依赖与修订快照；
`source_articles_read` 默认空数组，不能把模型已有证据 ID 当成本次读取原文的记录。
已有账号的创作入口、工作流与状态若要求每次检索范文，更新这部分流程并保留人工风格规则与历史记录。
批量选题逐篇记录 pending/writing/reviewed/illustrated/exported 与产物；图片、排版、发布分别记状态。
当前账号根下的 `作者风格系统/`、`创作/`、`排版/`、`发布/` 属于派生产物，扫描时排除并记录原因，
不把分析、生成稿、微信回读、准备快照和预览当作新范文。外部参考目录中的同名目录仍正常盘点。
不能只靠对话记忆推测某篇已完成，也不能用成功写文件代替内容质量验收。
OCR、全文内容分析、视觉阅读和图文模型就绪分别记录；图片正文未生成或未核对时，文字审稿通过不等于图文完成。
图片文章标注还须绑定 `joint_analysis_file/joint_analysis_sha256`，按 visual-style.md 保存整篇图文联合证据。
index/retrieve 校验联合记录与当前原图、提取版本一致；旧勾选不能自动迁移为新证据。
此审核只影响建库/更新/追溯，不改变日常依赖已保存模型、无需访问原文的创作约定。
