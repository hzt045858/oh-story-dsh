# 按已保存风格模型创作

执行 [workflow-control.md](workflow-control.md) 的任务输入 → 方案审核 → lock → compile/导入 → 逐图审核 → assemble → 成稿审核 → 导出链路。
这里描述 Agent 的内容判断，不是可以绕开脚本门禁的另一条流程。输入/审核/参数由 Agent 根据真实用户任务和观察生成。

## 恢复与选题路由

先读当前账号配置、处理状态、创作入口、默认字数、禁用规则和全局模型；核对 style_release.py check 的已保存验收。
先确认主要内容形式与用户本轮要求。图片型账号加载已保存的图文风格模型，执行
[visual-style.md](visual-style.md) 的新选题流程；图片正文是默认交付，不是额外配图。
视觉模型缺失时先补足分析；明确只要文字时可交付文案，不声称已完成图片文章。
日常创作只依赖已保存的模型与创作规则，不扫描参考目录、不调用 retrieve、不读取参考文章全文或文章卡片。
无需先读取全量索引、检查原文哈希或证明原文仍在；模型中的证据 ID、源哈希与短证据是分析溯源信息。
记录本次实际加载的模型文件哈希，以便复现采用的风格版本。
根据用户选题判断主类、子题、表达任务、受众、情绪、标题方向、是否已有主题及是否需跨主题迁移。
只读对应主题模型；未知主题用全局模型和已保存的迁移边界，明确该主题尚无专属模型。
低置信度主题沿用已记录的适用范围，不把局部规律当成稳定风格。
全局模型缺失、为空或仅有形容词而无可执行规则时，先报告尚未具备按风格创作的条件，回到建库补足模型，
不能临时挑几篇原文代替风格模型。原文不可用但有效模型已保存时，仍可正常创作。
只有新增资料或用户要求更新风格时才进入增量分析，并在该阶段复核受影响规则的证据源哈希。

用户提供选题时直接使用；需要推荐时，根据已保存的受众、主题与风格规则提出候选。
可结合用户提供的阅读量、发布日期与来源判断读者需求；没有真实阅读数据时不能伪称爆款。
围绕当前读者需求找到本篇独特问题和观点，不为选题推荐重新读取作者原文。

## 风格模型的应用

从全局与对应主题模型中选择适合本题的规则，落实到观察角度、读者关系、语言节奏、结构、论证和结尾。
先建立本题的独立观点和内容，再应用风格；模型中的短证据用于理解规则，不作为待改写段落。
不因缺少同题原文而停止写作，也不把原作者的具体观点、人物和经历当成当前选题的内容。

原文检索只用于建库、用户要求的风格更新或证据追溯。用户明确要求参考某篇原文时，
作为本次附加资料单独记录用途与 ID，不把这一例外写回日常创作的必需步骤。
新文章的事实核验仍可读取可靠外部资料；事实资料与作者风格学习分开记录。

旧账号若保存了“每次检索 3～5 篇范文”等要求，先将创作入口、新选题工作流和下次启动说明更新为本流程。
原有参考筛选规则仅保留作分析或追溯用途；保留人工风格内容、禁用项与历史创作记录，不重建已完成模型。

## 创作提示词

把以下模板的括号部分替换为真实资料，使用当前 Agent 写作：

> 新选题：【选题】。目标读者：【受众】；主要表达任务：【任务】；目标字数：【明确要求或主题默认】。
> 依据已保存的全局稳定风格、适用的主题模型、创作参数与禁用规则写作，不检索或读取作者原文。
> 输出形式：【用户要求或模型默认】。图片型正文依据已保存图文模型同时创作每图的文字、画面和图文关系，实际生成后按序组成正文。
> 先确定本题独特矛盾、读者真正困惑、核心判断、论证顺序、现实场景和待核实事实，
> 再应用风格。模仿可迁移的思维方式、观察角度、读者关系、语言节奏和论证经验，不先套句式再填内容。
> 每篇至少有两个本选题独有的内容元素：现实场景、矛盾、分析角度、可核实案例、机制、比喻、结构或结尾落点。
> 不复制旧句子、标题、人物、案例、数据，不把旧文章换词重写；不继承原作者的个人经历或身份。
> 事实、推断、意见和虚构示例分别处理：事实需可靠来源；推断写清条件；示例明确为假设场景；
> 不虚构研究、专家、书名或出处。无法确认的事实删去或改成不声称存在外部证据的分析。
> 过滤本账号的身份与平台模板禁用项。默认不输出原作者简介、课程广告、二维码、关注引导或固定签名。
> 用户提供的新署名只在必要位置出现；未指定就不编造。
> 完整展开论证，正文达到要求，不用分析说明挤占正文。
> 默认输出文章标题和完整正文，正文可以是文字、图文或图片组，按账号模型决定；不把图片文章改成长篇纯文字。

不要让每篇都“你有没有发现”开头、都三段分点、都套心理学/经济学、都复用同一种比喻或结尾。
与同账号最近生成稿比较角度、结构、例子和句子，必要时重写重复部分。

## 审稿与落盘

审稿分四组：

- 内容：回答选题、有核心判断、具体场景、完整论证与可用结论，避免空泛鸡汤，达到字数。
- 风格：逐项对照本次采用的全局与主题规则，记录正文体现规则的位置；节奏自然，不把模板当风格。
- 图片正文：实际检查图片文字、画面、排版、图文对应、组图推进和一致性，不能只审文案；文件检查见 visual-style.md。
- 身份与平台：原 IP/账号/运营者昵称、课程品牌、广告词、固定开头结尾、引流模板已排除。
- 差异化：至少两个独有元素，没有复制旧案例/比喻/句子，没有所有主题共用固定结构。

核实文中具体事实，记录来源 URL、查阅日期和支撑的论断。未能核实的保留到审稿待办而不作为已证实事实发布。
正文保存为 `创作/<文章ID>/article.md`，审稿记录保存为同目录 `审稿.md`。
选题、分类、受众、目标字数、独有元素、事实来源、content_mode 与执行要求写入 `任务输入.json`，精确文案写入 article.md。
`创作记录.json` 由 article_workflow.py lock 写入 `workflow: "controlled-wechat-v1"`，保存实际模型哈希、已审输入签名及修订。
状态使用 article_workflow.py status 由真实依赖推导；不要另手写一个 completed 布尔值。图片未就绪时为 images_pending，不能标为图文完成。
`source_articles_read` 仅记录本次实际读取的作者原文，日常创作为空数组；模型内的证据 ID 不计为本次原文读取。
若有用户明确指定的原文附加资料，另记授权用途，不伪称仅凭模型生成。
用户只要正文时不在聊天里附长篇分析。

批量任务逐篇经历选题路由、模型应用、写作、审稿、保存，不把所有选题套进同一固定结构。
记录每篇状态与产物后再下一篇。用户只改一篇时不重写整个批次。
