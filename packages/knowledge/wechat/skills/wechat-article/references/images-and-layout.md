# 配图、排版与交付

所有新建及明确迁移的公众号任务先执行 [workflow-control.md](workflow-control.md)。下文是图片工具与排版能力，
不能绕过任务输入、模型验收、已审图文计划和逐图语义检查。提示词由 article_workflow.py compile 生成，不在调用时随意重写。

文字型文章的配图按需追加；图片型账号按 [visual-style.md](visual-style.md) 生成图片正文，图片是主要内容。

## 图片规划

从已审校文章提取读者、核心矛盾、具体实体和情绪；读取账号视觉风格与用户本轮要求。
图片型读取已保存图文模型和原创图文计划，按每图精确文字与画面执行，不先套用通用长文配图方案。
先规划封面与必要图位，不固定凑图片数量。每个图位说明用途、对应段落、内容依据、画风、
主体、构图、色板、比例、文字（可为空）、参考图和目标文件。

- 封面：传达本篇具体主题，按发布目标保留主体/文字安全区；需要宽封面与方缩略图时分别检查裁切。
- 文字型配图：信息图解释结构/流程，场景图表达真实或明确虚构的情境；删除后不影响理解和节奏的装饰图可以省略。
- 图片型正文：每张同时承担文字与画面表达，依照模型的布局和多图推进生成，不能按装饰图标准删去。
- 用户图片、已核实的截图与账号素材适合时复用；不生成虚假的后台截图、收益证明或“真实新闻照片”。
- 字卡、数据图、流程图可用程序模板保证文字与数字正确。AI 场景/插画用当前图片工具或 API。
- 同篇统一风格，账号整体保持可识别特征；不许假设同一提示词必然得到一致人物。

把最终生图提示词通过受控编译保存到文章目录 `prompts/`，实际图片放 `images/`。不要把文件路径写到对外正文中。
示例提示词结构：

> 用途：【公众号封面/正文解释图】；文章主题：【具体问题】；表达：【本图帮助理解什么】。
> 主体与动作：【可观察场景】；构图：【视觉焦点和留白位置】；风格/配色：【账号规则】；
> 比例：【目标比例】；文字：【精确短文字或不含文字】；参考图作用：【身份/风格/配色】。
> 不出现原作者账号名、二维码、广告与没有依据的数据。

## 图片执行

### 手工/聊天生图的临时接入

未接生图 API 时，可由用户指定的聊天生图工具生成实际图片，再导入既有图文计划：

```text
python "{skill}/scripts/import_article_image.py" --article "文章目录" --card card-01 --source "实际存在的图片.png" --origin chatgpt-image
```

必须先确认实际图片文件可访问。聊天内显示的图片不等于已保存到 DSH 本机工作区；两边文件系统不可互通时，
明确图片仍在聊天中，不虚构本地路径。导入依据计划的 output 写入新版本，原件、已用图片和旧回执都不覆盖。
来源标记只是导入者声明，不冒充本项目 API 请求回执；状态为 `review_pending`，不会自动生成审稿通过标记。
之后仍逐图检查文字、场景、图文关系和整组节奏，再生成图文检查及 article-illustrated.md。
后续生图模型使用同一计划、images/ 输出和检查契约，无需重做建库或整套创作流程。

优先使用用户选择且当前可见的图片能力。DSH bridge 会提供已打包的图片 adapter 路径，
可通过本 Skill 的 `article_images.py` 复用真实图片接口；它不调用短剧项目管理脚本。
账号配置与用户要求决定是否实际生成、数量上限和采用哪个服务。不要因为查看图片方案而调用付费 API。
凭据只由图片执行环境读取；DSH 的文字模型配置不等于图片服务可用。

每张图一个 JSON 任务，放在当前文章目录，所有相对路径均相对于这个目录。
新任务先 lock 再 compile，编译器写入 provider、requirements 和 control（账号/图位/输入签名），执行器强制复算核对。
下面只展示底层旧任务的基础字段，不能据此手写新任务绕过 control；完整字段由编译器产生：

```json
{
  "id": "cover-v1",
  "article_file": "article.md",
  "article_sha256": "article.md 的 SHA256",
  "prompt_file": "prompts/cover-v1.md",
  "prompt_sha256": "提示词文件的 SHA256",
  "output": "images/cover-v1.png",
  "references": [],
  "parameters": {"size": "1536x1024", "quality": "medium"}
}
```

这里的尺寸是生成底图示例，最终封面裁切按目标平台和实际画面决定。
参考图只支持该 adapter 接受的本地文件；先保存于文章目录中，再以相对路径引用。

```text
python "{skill}/scripts/article_images.py" "文章目录/cover-v1.json" --adapter-script "DSH bridge 给出的 provider_adapters.py" --check
python "{skill}/scripts/article_images.py" "文章目录/cover-v1.json" --adapter-script "DSH bridge 给出的 provider_adapters.py" --run
```

check 只验证任务、依赖与已存在的输入，不调用服务。run 仅在本轮范围已包含实际生图时执行。
提示词/正文哈希变了先更新方案；图片路径与任务 ID 按版本递增，不覆盖已采用版本。
受控任务以本图实际内容/风格/素材/参数签名判定失效；仅修改另一图的文案或场景，不要求本图重复付费生成。
回执成功且图片存在才记为完成；调用失败或中断后可能已计费，先核对回执/服务结果，不盲目自动重试。
adapter 返回的脱敏请求 ID、错误类别、错误码和 HTTP 状态保存在回执的 `provider_error` 中供核对；
其中 `retryable` 仅记录服务建议，不解除未知结果的自动重试限制。原始响应、日志和错误消息不写入回执。
没有图片服务时交付提示词并标“图片待生成”，不能用占位图冒充生产结果。

需要更细的插图构图时，按需阅读已打包的
[baoyu 提示词构造参考](../../../third_party/baoyu/illustration-prompts.source.md)，
把信息类型、区域、标签、颜色和风格填成本文实际内容。执行仍使用本项目图片脚本与 DSH 工具。

所有实际图片逐张检查：能打开、格式正确、主体与文字可辨、裁切合理、无原账号身份残留、
与段落内容一致。错字图片重新生成或改为无字底图配明确的排版文字，不把错误数据留给读者。
选择后复制正文为 `article-illustrated.md`，把图插到对应段落；保留原始 `article.md`。
新受控任务由 article_workflow.py assemble 完成上述组合，保留覆盖前历史；不要手动插入计划外内容后直接发布。
图片型按图文计划组成图片正文，`article.md` 保留精确文案作为内部创作源；不要再附一份重复长文。
封面通常只进入封面字段，不强行插到正文开头。图注用于补充信息，不展示内部生图指令。

## 程序字卡与信息卡

标题字卡、清单和少量精确文字可使用自行实现的 `article_card.py`，不依赖付费生图服务。
参考 [card.example.json](../assets/card.example.json)，把 title、points、footer 改成实际正文信息。
kind=cover 输出 1200×510，kind=card 输出 1080×1440。长文字自动换行与缩小，放不下时明确报错。
中文字体优先使用当前系统字体；没有合适字体时提供 --font，不能用缺字字体生成后宣称合格。

```text
python "{skill}/scripts/article_card.py" "文章目录/prompts/card-v1.json" --output "文章目录/images/card-v1.png"
```

字体、输入哈希和图片哈希写入回执，输出须用新版本文件名。生成后检查字形、行距和边界。
程序字卡是本项目实现，未复制 guizang 的 AGPL 封面模板。
它是纯文字卡工具，不包含漫画场景；漫画型账号不能仅用此工具冒充图文风格完成。

## 学习排版与导出

按原文流程读取用户提供的一篇对标文章 HTML，提取字号、行距、段距、主题色、标题层级、
引用和图片样式；不继承原账号广告、身份、二维码或追踪代码。需要图文视觉核对时在当前可见浏览器检查。
将可复用配置写入 `排版/theme.json`，例如：

```json
{
  "font_size": 16,
  "line_height": 1.8,
  "paragraph_gap": 20,
  "text_color": "#333333",
  "accent_color": "#24755b",
  "background_color": "#ffffff"
}
```

渲染脚本用 Markdown 解析器和内联样式输出 HTML，支持标题、列表、引用、表格、代码、链接、图片。
本地图片必须在文章目录内且可读；导出页内嵌图片便于本地预览。该文件是预览产物，
上传微信时由已集成的发布脚本上传图片并换成平台 URL，不能声称复制 data URL 就完成发布。
默认禁用源 Markdown 中原始 HTML，不执行或透传对标页面脚本。
自定义排版超出主题参数时，由 Agent 基于用户要求生成兼容 HTML，并实际检查，不自动修改渲染器来套单篇模板。

```text
python "{skill}/scripts/render_article.py" "文章目录/article-illustrated.md" --output "文章目录/article.html" --theme "{account}/排版/theme.json"
```

用可见浏览器检查窄屏与桌面：图片非空、文字不溢出、标题层级清楚、长链接和表格不挤坏正文。
正式导出前要求成稿审核通过；渲染回执绑定当前成稿签名和 HTML/主题，实际预览后写排版检查。
审稿前仅预览时用 --draft 且输出另一个文件名，不能覆盖 article.html 或产生正式导出回执。
排版参考、账号 theme 与本 Skill 形成原文要求的可复用排版能力；只改主题时不重写正文或重生成图片。

## 发布边界

继续阅读 [publishing.md](publishing.md)，使用内置 `wechat_publish.py` 完成账号配置、发布准备、
图片上传、草稿创建/更新、手机预览、公开发布或群发，以及状态查询和断点核对。
用户已明确的账号与动作沿用；缺少凭据或权限时列明缺项并保留本地交付，不冒充远端成功。
